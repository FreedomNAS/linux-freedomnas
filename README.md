# linux-freedomnas

The FreedomNAS kernel for the Arch, Artix and Debian editions: Arch's
`linux-lts` with the OpenZFS modules built into the same package, the way
Proxmox ships its kernels. `PKGBUILD` builds it for Arch; `debian/` builds
the same sources, patches and config with Debian's own tooling.

A NAS whose `zfs.ko` is built by DKMS on the machine stops booting the first
time that build fails. Here the kernel, the ZFS modules and the matching
userspace are compiled together from pinned sources, so an update brings all
of them or none.

| Package | Contents |
|---------|----------|
| `linux-freedomnas` | kernel and modules, ZFS in `extra/zfs`; conflicts with `zfs-dkms` |
| `linux-freedomnas-headers` | headers for building out-of-tree modules |
| `zfs-utils-freedomnas` | OpenZFS userspace and dracut module at the exact version in the kernel; provides `zfs-utils` |

The kernel package depends on `zfs-utils-freedomnas` of its own version and
release (split packages of one build share them), so pacman never pairs a
kernel with a different userspace. Init scripts are not in
`zfs-utils-freedomnas`: they come from each init system's package
(`zfs-openrc`, `zfs-dinit`, ...).

### Debian

| Package | Contents |
|---------|----------|
| `linux-image-<kver>` | kernel in `/boot`, modules, ZFS in `extra/zfs`; conflicts with `zfs-dkms` |
| `linux-headers-<kver>` | headers in `/usr/src/linux-headers-<kver>` |
| `linux-image-freedomnas`, `linux-headers-freedomnas` | depend on the newest of the two above |
| `zfsutils-freedomnas` | OpenZFS userspace, zed, PAM and dracut modules; provides and replaces `zfsutils-linux`, `zfs-zed`, `zfs-dracut` and Debian's ZFS libraries |

`<kver>` is the kernel release, e.g. `6.18.54-1-freedomnas`. The kernel
packages carry it in their name, as Debian's do, so an update installs the
new kernel beside the old one and the `-previous` UKI keeps its modules;
`apt autoremove` retires old kernels. Only one `zfsutils-freedomnas` can
be installed, so a kernel depends on it at its own version or newer: the
new kernel brings the new userspace, and the previous kernel stays
bootable beside it. The kernel package's scripts run
`/etc/kernel/postinst.d`, where `zz-dracut-uki` rebuilds the UKI.
`zfsutils-freedomnas` enables the same ZFS systemd units Debian's
`zfsutils-linux` and `zfs-zed` do, and ships no SysV scripts.

`debian/rules` reads the versions from `PKGBUILD`; nothing Debian-specific
needs editing for an update. `debian/control` and the kernel package
scripts are generated by `make -f debian/rules prepare`.

## Following upstream

The kernel parts follow `archlinux/packaging/packages/linux-lts` (taken at
6.18.54-1, commit b51edfc8); the docs package is dropped. Following an Arch
update means taking its `pkgver`, patches, `config.x86_64` and checksums.
`config.x86_64` stays Arch's file as is: what FreedomNAS leaves out (Rust,
sound, Bluetooth, TV tuners, nouveau and old Radeon, and a few subsystems
no NAS uses) is in `config.freedomnas`, merged over it before
`olddefconfig`; the build fails if an option there ends up set anyway.
Wi-Fi, i915/xe and amdgpu stay in.
A new OpenZFS release means `_zfsver` and its checksum; the tarballs are
checked against the release key of Tony Hutter
(`4F3BA9AB6D1F8D683DC2DFB56AD860EED4598027`, in `keys/pgp/`).

## Building and publishing

The build and upload scripts live in
[freedomnas-arch](https://codeberg.org/FreedomNAS/freedomnas-arch), next to
the other Arch packages, and take this checkout as a path:

```sh
../freedomnas-arch/bin/build.sh ../linux-freedomnas           # about 45 minutes
../freedomnas-arch/bin/build.sh ../linux-freedomnas -- -R     # repackage only
```

For Debian the script lives in
[freedomnas-deb](https://codeberg.org/FreedomNAS/freedomnas-deb); it fetches
and verifies the tarballs listed in `PKGBUILD`, then runs
`dpkg-buildpackage` on a copy of this checkout:

```sh
../freedomnas-deb/bin/build-kernel-debs.sh ../linux-freedomnas
```

Both workflows clone this repository and rebuild the kernel only when its
version is not in the registry yet.
